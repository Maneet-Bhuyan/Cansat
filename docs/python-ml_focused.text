1. EXECUTIVE SUMMARY & ARCHITECTURAL INVERSION
--------------------------------------------------------------------------------
Original State:
- Frontend-heavy architecture where the browser's Web Serial API directly ingests
  telemetry, computes derived kinematics, runs state machine logic, and drives UI.
- Python backend acted as an auxiliary service called intermittently.
- High visual weight on index.html (~150 KB), making the project appear as a web
  development project rather than an aerospace AI & Machine Learning suite.

Target State ("Heavy Python Brain / Thin Web Client"):
- Python is the primary flight computer, ingestion engine, and analytics brain.
- Python manages dual hardware serial links (COM1: CanSat LoRa, COM2: ESP32-CAM ESP-NOW).
- All signal processing (Extended Kalman Filter, attitude estimation, atmospheric
  sounding thermodynamics via MetPy) runs strictly in Python.
- Real-time multimodal machine learning (tabular kinematics + downward aerial vision)
  executes in Python and on the edge (TinyML on ESP32-CAM).
- The web interface (index.html) is reduced to a passive, thin telemetry viewport
  receiving pre-computed, synchronized flight packets via a unified WebSocket stream.
- The repository profile on GitHub reflects >75% Python through code modularization
  and Linguist vendoring overrides.

2. THE FOUR PILLARS OF PYTHON & ML TRANSFORMATION
--------------------------------------------------------------------------------

PILLAR 1: INGESTION & SENSOR FUSION ENGINE (PYTHON BACKEND)
- Native PySerial asynchronous dual-port listener.
- Discrete Extended Kalman Filter (EKF) and 6-DOF IMU attitude fusion (ahrs/SciPy).
- Mathematical atmospheric sounding physics engine (Magnus-Tetens, ELR, Air Density).
- High-frequency full-duplex WebSocket dispatcher streaming at 60 Hz.

PILLAR 2: TINYML EDGE VISION & COMPUTER VISION PIPELINE
- Deep learning aerial classification and hazard patch segmentation (MobileNetV1-0.25).
- Model trained on verified remote sensing data (EuroSAT Sentinel-2 aerial dataset).
- Post-training INT8 quantization for sub-milliwatt edge microcontroller deployment.
- Auto-generation of optimized C++ flatbuffer byte arrays (model_data.h) for ESP32.
- Onboard execution via TensorFlow Lite for Microcontrollers (TFLM) on ESP32-CAM.

PILLAR 3: MULTIMODAL REAL-TIME FLIGHT DECISION SYSTEM
- Real-time multimodal fusion: Aligning downward 3x3 Safe Landing Area Index (SLAI)
  matrices from the camera with barometric descent velocity and GPS drift vectors.
- Automated Anomaly Root-Cause Analysis: Decomposing PyOD Isolation Forest anomaly
  scores into contributing sensor/actuator dimensions.
- Gradient Boosted Apogee Regressor predicting peak altitude before apogee event.

PILLAR 4: SCIENTIFIC RESEARCH SUITE & BENCHMARKING (NOTEBOOKS & CLI)
- Jupyter analysis notebooks for peer-reviewed academic validation.
- Skew-T log-P atmospheric thermodynamics profiles using MetPy.
- Model ablation studies comparing Random Forest, XGBoost, and HMM state classifiers.
- Quantization efficiency benchmarks: FP32 vs. FP16 vs. INT8 latency, memory, and energy.

4. MODEL SPECIFICATIONS & HARDWARE BUDGET
--------------------------------------------------------------------------------

A. Edge Model (TinyLandingNet on ESP32-CAM Microcontroller):
- Architecture: TinyLandingNet (Depthwise Separable CNN with Pointwise 1x1 Convolutions)
- Input Dimensions: 64x64 RGB (or 320x240 QVGA segmented into 3x3 spatial sectors)
- Output: 4-Tier Safe Landing Area Index (SLAI): SAFE_LZ, OBSTACLE_CANOPY, CRITICAL_HAZARD, WATER_HAZARD
- Total Parameters: 7,320 (quantized to 8-bit signed integers, `int8_t`)
- Flash ROM Footprint: 7.15 KB (`firmware/esp32_cam_airborne/model_data.h`, target < 25 KB)
- Peak SRAM Footprint: < 40 KB (comfortably fits in 520 KB internal ESP32 SRAM, no PSRAM required)
- Computational Complexity: 783,360 MACs (1.567 MFLOPs per inference)
- Inference Latency:
  * Airborne ESP32-CAM (Xtensa LX6 @ 240 MHz): ~16.3 ms per inference (Target: < 150 ms)
  * Ground Station ONNX Runtime (CPU): 0.055 ms per inference (18,073 FPS throughput)
  * Ground Station PyTorch CUDA (RTX 4060 GPU): 0.614 ms per inference (1,628 FPS throughput)
  * Full 3x3 Spatial Grid + Evasion Heading: 4.23 ms (236.6 FPS) on QVGA stream
- Classification Performance (N = 4,050 Holdout Test Samples):
  * Best Validation Accuracy: 93.80% (target >= 90%)
  * Overall Test Accuracy: 93.04%
  * Macro F1-Score: 93.21% (target >= 88%)
  * Per-Class F1: SAFE_LZ: 93.13%, OBSTACLE_CANOPY: 96.21%, CRITICAL_HAZARD: 94.01%, WATER_HAZARD: 89.48%
- Duty Cycle: 1 Hz to 5 Hz during parachute descent phase


B. Ground Station Models (Python Backend):
- Flight Phase Classifier: Random Forest (n_estimators=120, max_depth=12), Accuracy: 99.61%
- Anomaly Detection: PyOD Isolation Forest (contamination=0.01) with feature attribution
- Apogee Estimation: Gradient Boosting Regressor (n_estimators=100, max_depth=5)
- Multimodal Fusion: Bayesian update combining visual landing hazard with GPS drift speed
