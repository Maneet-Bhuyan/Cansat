1. PROJECT CONTEXT
--------------------------------------------------------------------------------
Ground Station software suite for a sounding atmospheric pico-satellite (CanSat).
Unbranded, competition-ready Web dashboard. No platform selection. No CubeSat
modals. Dedicated CanSat scope only.

Title: Ground Station - UNIVERSE TELEMETRY

--------------------------------------------------------------------------------
2. SYSTEM ARCHITECTURE & DATA FLOW PIPELINE
--------------------------------------------------------------------------------
1) CanSat Flight Unit: ESP32/STM32 + sensors broadcasts telemetry via RF
   (LoRa / 433 MHz / 868 MHz / 915 MHz).
2) Ground Receiver Station: RF transceiver connects to operator PC via USB UART
   (Serial COM port) at 115200 baud.
3) Web Ground Station: Browser dashboard connects to USB receiver via Web Serial
   API (navigator.serial), reads newline-delimited CSV strings, computes derived
   kinematics/attitude, updates live charts/maps, renders 3D orientation, and
   exports competition CSV logs.

--------------------------------------------------------------------------------
3. INBOUND SERIAL PACKET SCHEMA
--------------------------------------------------------------------------------
Newline-delimited (\n) ASCII CSV:

  temp,pressure,altitude,gx,gy,gz,ax,ay,az,lat,lon,humidity,batteryVoltage

Field indices:
  [0]  temp            Ambient temperature °C (Float)
  [1]  pressure        Barometric pressure hPa (Float)
  [2]  altitude        Barometric/GPS altitude m (Float)
  [3,4,5] gx, gy, gz   Gyroscope angular rates °/s (Float)
  [6,7,8] ax, ay, az   Accelerometer forces G (Float)
  [9,10] lat, lon      GPS WGS84 decimal degrees (Float)
  [11] humidity        Relative humidity % (Float)
  [12] batteryVoltage  Cell potential V (Float)

Malformed / incomplete lines MUST be ignored without crashing the UI.

--------------------------------------------------------------------------------
4. DERIVED TELEMETRY FORMULAS (computed in JS per packet)
--------------------------------------------------------------------------------
1) Timestamp:
     ISO 8601  =  new Date().toISOString()

2) Vertical Speed (m/s):
     v_spd = (altitude_t - altitude_{t-1}) / Δt

3) Accelerometer Magnitude (g):
     accelMag = sqrt(ax^2 + ay^2 + az^2)

4) Pitch Angle (deg):
     θ = atan2(ay, az) * (180 / π)

5) Roll Angle (deg):
     φ = atan2(-ax, sqrt(ay^2 + az^2)) * (180 / π)

6) Battery Percentage:
     Battery% = clamp( (V_bat - 3.20) / (4.20 - 3.20) * 100, 0, 100 )

--------------------------------------------------------------------------------

[2026-08-30T18:12:00Z] ACTION: Fixed flight phase transition engine and completed flight profiles across all test cases.
FILES MODIFIED:
  - E:\Cansat\index.html
  - E:\Cansat\generate_test_cases.ps1
  - E:\Cansat\test_cases\*.csv (10 profiles regenerated)
  - E:\Cansat\selftest.ps1
  - E:\Cansat\project_log.txt

ROOT CAUSE & RESOLUTION:
1. State Machine Transition Bug:
   - In `index.html`, the ascent-to-apogee transition check required `alt >= apogee && vSpd < 0.5`. During ascent, `vSpd` was high positive. Once descent began, `alt` dropped below `apogee`, making `alt >= apogee` evaluate to false. This prevented the state machine from ever entering `APOGEE_BURST`, leaving the dashboard stuck in `BALLOON_ASCENT`.
   - Resolution: Updated `updateFlightPhase` to trigger `APOGEE_BURST` when `hasClimbed` and either `(alt <= apogee - 2.0)` (peak crossed), `(vSpd <= 0.2 && alt >= apogee - 15.0)` (stalled near peak), or `(accelMag > 2.0)` (ejection shock).
   - Robustly wired subsequent transitions to `PARACHUTE_DESCENT` (`vSpd < -1.8`) and `TOUCHDOWN_RECOVERY` (`alt <= pad + 4m` and velocity settled).

2. Test Case Profile Data Completeness:
   - Regenerated all 10 CSV profiles via updated `generate_test_cases.ps1` to ensure every dynamic flight profile (01 through 09) features complete lifecycle telemetry:
     Pad (0..20s) -> Steady Ascent -> Apogee Burst / Shock -> Parachute Canopy Descent -> Ground Touchdown with post-landing stabilization.
   - Profile 10 correctly remains in `PAD_IDLE` as a static pad integration test.
